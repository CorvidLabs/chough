### REQUIREMENT REQ-cli-043

Knowledge directory built and kept current. With the librarian on, which is the default, `chough init` SHALL create the knowledge directory (`knowledge/`, or `library-dir`) with `index.md`, `journal/` and `lessons/`, built and bounded in memory first and written create-only, so an existing directory is preserved byte-identical and reported as `preserved`; when the index cannot be built or bounded, `chough init` SHALL still succeed, write no knowledge file and report the library as `refused` with the reason. `knowledge/index.md` SHALL be the vault's reading guide, generated from its sources: front matter with `id`, `title`, `type: guide` and `tags`; where to start, in plain words; the journal and its feed as the timeline of archived changes, with `.specsync/archive/changes/` linked for changes archived before the journal began (REQ-records-011), and the newest 10 posts; where things live, linking `hi/`, `specs/`, `.specsync/archive/`, `.chough/README.md`, `.chough/archive/sessions/` and `fledge.toml`; the open bugs, at most 20, blocking bugs first and then the newest by `created`, each linked, with their total and, when more are open, a link to `.chough/bugs/` and `chough bug list` named for the rest, so the number of open bugs never takes the index over its bound; the project's rule, skill, decision and policy files that exist and Git does not ignore (`AGENTS.md`, `CLAUDE.md`, `hi/AGENTS.md`, the installed and bundled workflow skill, `docs/DECISIONS.md`, each module's context and lesson source, `.specsync/sdd.json`); every lesson, linking each module's lesson source with its count of recorded lessons, every file in `knowledge/lessons/` and the newest 3 archived lesson bundles; and the existing `library/` snapshots and `briefs/`. It SHALL link and SHALL copy no text from what it links. When `chough stage advance` moves into done and its save succeeds, the helper SHALL, after the session's archive step (REQ-history-006), write the journal post of REQ-records-011 and SHALL NOT regenerate `index.md` or `feed.xml`: the directory is rebuilt at release, by the release check of REQ-cli-047, so a change's pull request leaves it behind its sources and no two open pull requests edit it (#289). It SHALL report the result as `applied.librarian_index` with status `deferred` and the index path, `skipped` with the librarian off, or `refused` with its reason. A refusal SHALL NOT undo or refuse the move into done, nothing SHALL be built with the librarian off, and no gate SHALL read the directory. Every Chough reader that lists or counts open native changes SHALL skip a directory under `.specsync/changes/` that holds no change files, such as one a branch switch left (#148). Trace: KNOW-1, KNOW-4, KNOW-5, KNOW-12, KNOW-15, KNOW-31, KNOW-33.

Acceptance Criteria
- With defaults, `chough init` reports the library `created`, writes `knowledge/index.md`, `journal/` and `lessons/`, and `chough next --json` names `knowledge/index.md`.
- With an existing `knowledge/index.md`, `chough init` reports `preserved` and leaves it byte-identical; with an index that cannot be bounded, `chough init` succeeds, reports `refused` naming the 65536-byte bound, and leaves no knowledge directory.
- With defaults, `stage advance` into done writes the journal post, reports `librarian_index` `deferred` with the index path, and leaves `index.md` and `feed.xml` byte-identical; `chough library index` then makes `library index --check` pass (#289).
- `knowledge/index.md` links at most 20 open bugs, blocking first and then the newest, states their total, and links `.chough/bugs/` and names `chough bug list` when more are open. It links every rule, skill, decision and policy file that exists and Git does not ignore, and none that is missing or ignored.
- With 1,500 open bugs, `chough library index` builds the index within the 65,536-byte bound and `library index --check` passes.
- `knowledge/index.md` links each module's lesson source with its lesson count, every file in `knowledge/lessons/`, the newest 3 lesson bundles, the journal, its feed and `.specsync/archive/changes/`, and holds no lesson, criterion or requirement text.
- With the librarian off, `stage advance` into done writes no post, reports the index `skipped`, creates no knowledge directory, and done is still recorded.
- After a branch switch leaves an empty `.specsync/changes/<id>/deltas/`, `library index`, `next`, `gate list` and `doctor` treat it as no open change, and `library index --check` passes in a fresh clone of the same commit (#148).
- In a repository whose `.gitignore` ignores `.grok`, after `chough init --host grok` and a commit, the index links nothing under `.grok/`, and `library index --check` passes in the working tree, with the ignored skill copy present or removed, and in a fresh clone (#245).

### REQUIREMENT REQ-cli-047

No conflicting files. When two branches each record Chough work, merging one into the other SHALL need no hand-resolved conflict in a file Chough writes (DRIVE-12). Case definitions MAY be split per change: `.chough/cases/<module>.<part>.cases.toml` SHALL hold cases of `<module>`, which its `module` field SHALL name, `<part>` SHALL use letters, digits, `-` and `_`, and case IDs SHALL stay unique across all files. `chough library index --check` SHALL write nothing and SHALL fail, naming each generated knowledge file (`index.md` and `journal/feed.xml`) that is missing or differs from a rebuild, with line endings ignored; the release check (`fledge run release-check`) SHALL run `chough library index` and then it on the release preparation branch before that branch merges, and no verify, CI or pull request lane SHALL run it, since a change's pull request leaves the generated files behind their sources (#289). Generated knowledge SHALL never need a hand-resolved conflict: the project SHALL declare `<knowledge dir>/index.md merge=chough-generated` and `<knowledge dir>/journal/feed.xml merge=chough-generated`, where the knowledge dir is `knowledge/` or `library-dir`, and `chough library merge <base> <ours> <theirs>`, that driver, SHALL keep ours byte for byte and exit 0, so a merge commit never holds a union of two feeds that is not valid XML, and the next `chough library index`, at release at the latest, rebuilds both from the merged sources. `chough bug merge <base> <ours> <theirs>`, a Git merge driver for `.chough/bugs/*.md` declared in `.gitattributes`, SHALL merge two edits of one bug: a front matter field only one side changed SHALL take that change, list fields SHALL keep base's entries and then each side's additions without duplicates, `updated` SHALL be the later one, the Log SHALL keep base's lines and then each side's added lines in order without duplicates, a body paragraph only one side changed SHALL take that change, the result SHALL be a valid bug record written as bug commands write it, and a field or paragraph both sides changed differently SHALL be left for a human with `ours` unchanged and a nonzero exit. `chough init` SHALL set up both drivers, so two branches merge with no hand setup. It SHALL append each of `.chough/bugs/*.md merge=chough-bug`, `<knowledge dir>/index.md merge=chough-generated` and `<knowledge dir>/journal/feed.xml merge=chough-generated` that `.gitattributes` does not declare, after its last line, creating the file when it is absent and changing no line already in it. A line counts as declared when its first field is that pattern and another of its fields is that `merge=` attribute. In a Git work tree, it SHALL set `merge.chough-bug.driver` to `chough bug merge %O %A %B` and `merge.chough-generated.driver` to `chough library merge %O %A %B` in the clone's local Git config, each only while Git has no command for that driver, so a command a person set is kept. It SHALL report both parts as `merge`, and neither SHALL fail init. Outside a Git work tree it SHALL write the lines and report the drivers `skipped`. `chough doctor` SHALL report a clone that lacks either driver or line (REQ-history-012). Trace: DRIVE-12, DRIVE-3, DRIVE-25.

Acceptance Criteria
- Two branches that each add a case in their own `cli.<part>.cases.toml` merge without conflict, and both cases load; a case ID defined in two files is refused.
- `library index --check` passes on a rebuilt vault, fails naming `index.md` or `feed.xml` after a hand edit, including an edit to a bullet that keeps its link, passes again after `library index`, and passes on a CRLF copy of a current file.
- The verify and CI lanes run no `library index --check`, and `fledge run release-check` runs `library index` and then `library index --check`.
- Two edits of one bug, one adding a note and verifying it and the other adding a note and an evidence link, merge with both Log entries, the evidence, the verified status and the later update time; two different status changes exit nonzero and leave ours unchanged.
- `git check-attr` reports `chough-bug` for `.chough/bugs/x.md` and `chough-generated` for `knowledge/index.md` and `knowledge/journal/feed.xml`.
- In a Git repository where `chough init` ran, with no other setup, two branches that each add a journal post merge with no conflict, the merged `feed.xml` parses as XML, and one `chough library index` makes `library index --check` pass, listing both posts.
- Over a `.gitattributes` that already declares some of the merge lines, `chough init` appends only the missing ones after its last line and changes no line. With `library-dir notes`, the lines name `notes/`. A driver the clone already sets is kept.

### REQUIREMENT REQ-cli-052

Several forward moves on one native read, and one read into done. `chough stage advance --to <stage>` SHALL move forward through each main stage, from the current one up to `<stage>`, as consecutive advances. `<stage>` SHALL be a main stage after the current one, and any other value SHALL be refused. Every refusal of `stage advance` SHALL apply, including a stage that is not active, a side stage and an open human gate (REQ-cli-030). Before recording anything, the helper SHALL check every step as `stage advance` alone would check it: its destination's native prerequisite (REQ-cli-008) and, on leaving test, the blocking-bug and unlinked-failure refusals. All steps SHALL share one `specsync change status` read, made only when a step has a native prerequisite. A refused step SHALL refuse the whole command, naming that step with its label and detail. Then no transition SHALL be recorded and the checkpoint SHALL stay byte-identical. Otherwise the helper SHALL record one `advance` transition per step, in order, each with its own gate label and the given note. It SHALL report the steps in order in `applied.steps`, with `applied.from` as the starting stage, `applied.to` as the target and `applied.gate` as the last step's label. `stage advance` without `--to` SHALL be unchanged.

On a move into done by `stage advance`, with or without `--to`, the move SHALL make exactly one native status read, the gate's, and the session archive and journal post of REQ-history-006 and REQ-records-011, and the deferred knowledge step of REQ-cli-043, SHALL make none. The response SHALL serve only that command and SHALL NOT persist. Trace: DRIVE-9, DRIVE-2, FLOW-2, LIFE-3, DRIVE-24.

Acceptance Criteria
- Under a per-change session (`chough session new`), with a counting SpecSync stub reporting an approved change at plan, `stage advance --to accept` exits 0 and runs `specsync change status` once. It records three advances (plan to build, build to test, test to accept) as three timeline entries of that session, reports them with their gate labels in `applied.steps`, and leaves the stage at accept.
- From intent, `stage advance --to plan` runs no native read and records two advances.
- Each of these refusals makes at most one native read, records no transition, and leaves the session file byte-identical:
  - at build with an open acceptance-blocking bug, `--to accept` is refused naming `refused:blocking-bugs` and the test to accept step;
  - at plan with the stub reporting draft, `--to test` is refused naming `refused:native-draft`;
  - a target at or before the current stage, a side, optional or unknown stage name, and an open human gate are refused.
- With the stub reporting an archived change with authenticated terminal evidence, and the librarian on by default:
  - `stage advance --to done` from test runs `specsync change status` exactly once and reports `session_archive` and `librarian_index`;
  - `stage advance` from accept to done also runs it exactly once, where before this change it ran twice.
- `stage advance` without `--to` records one transition, as before.
- Every test of new behavior above fails against main before the implementation, and passes after it. The unchanged plain advance passes both times. `fledge lanes run verify` passes.
