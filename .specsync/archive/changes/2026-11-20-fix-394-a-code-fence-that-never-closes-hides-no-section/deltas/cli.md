## MODIFIED

### REQUIREMENT REQ-cli-047

No conflicting files. When two branches each record Chough work, merging one into the other SHALL need no hand-resolved conflict in a file Chough writes (DRIVE-12). Case definitions MAY be split per change: `.chough/cases/<module>.<part>.cases.toml` SHALL hold cases of `<module>`, which its `module` field SHALL name, `<part>` SHALL use letters, digits, `-` and `_`, and case IDs SHALL stay unique across all files. `chough library index --check` SHALL write nothing and SHALL fail, naming each generated knowledge file (`index.md` and `journal/feed.xml`) that is missing or differs from a rebuild, with line endings ignored; the release check (`fledge run release-check`) SHALL run `chough library index` and then it on the release preparation branch before that branch merges, and no verify, CI or pull request lane SHALL run it, since a change's pull request leaves the generated files behind their sources (#289). Generated knowledge SHALL never need a hand-resolved conflict: the project SHALL declare `<knowledge dir>/index.md merge=chough-generated` and `<knowledge dir>/journal/feed.xml merge=chough-generated`, where the knowledge dir is `knowledge/` or `library-dir`, and `chough library merge <base> <ours> <theirs>`, that driver, SHALL keep ours byte for byte and exit 0, so a merge commit never holds a union of two feeds that is not valid XML, and the next `chough library index`, at release at the latest, rebuilds both from the merged sources. `chough bug merge <base> <ours> <theirs>`, a Git merge driver for `.chough/bugs/*.md` declared in `.gitattributes`, SHALL merge two edits of one bug: a front matter field only one side changed SHALL take that change, list fields SHALL keep base's entries and then each side's additions without duplicates, `updated` SHALL be the later one, the Log SHALL keep base's lines and then each side's added lines in order without duplicates, a body paragraph only one side changed SHALL take that change, the result SHALL be a valid bug record written as bug commands write it, and a field or paragraph both sides changed differently SHALL be left for a human with `ours` unchanged and a nonzero exit. `chough init` SHALL set up both drivers, so two branches merge with no hand setup. It SHALL append each of `.chough/bugs/*.md merge=chough-bug`, `<knowledge dir>/index.md merge=chough-generated` and `<knowledge dir>/journal/feed.xml merge=chough-generated` that `.gitattributes` does not declare, after its last line, creating the file when it is absent and changing no line already in it. A line counts as declared when its first field is that pattern and another of its fields is that `merge=` attribute. In a Git work tree, it SHALL set `merge.chough-bug.driver` to `chough bug merge %O %A %B` and `merge.chough-generated.driver` to `chough library merge %O %A %B` in the clone's local Git config, each only while Git has no command for that driver, so a command a person set is kept. It SHALL report both parts as `merge`, and neither SHALL fail init. Outside a Git work tree it SHALL write the lines and report the drivers `skipped`. `chough doctor` SHALL report a clone that lacks either driver or line (REQ-history-012). Trace: DRIVE-12, DRIVE-3, DRIVE-25.

Acceptance Criteria
- Two branches that each add a case in their own `cli.<part>.cases.toml` merge without conflict, and both cases load; a case ID defined in two files is refused.
- `library index --check` passes on a rebuilt vault, fails naming `index.md` or `feed.xml` after a hand edit, including an edit to a bullet that keeps its link, passes again after `library index`, and passes on a CRLF copy of a current file.
- The verify and CI lanes run no `library index --check`, and `fledge run release-check` runs `library index` and then `library index --check`.
- Two edits of one bug, one adding a note and verifying it and the other adding a note and an evidence link, merge with both Log entries, the evidence, the verified status and the later update time; two different status changes exit nonzero and leave ours unchanged.
- `git check-attr` reports `chough-bug` for `.chough/bugs/x.md` and `chough-generated` for `knowledge/index.md` and `knowledge/journal/feed.xml`.
- In a Git repository where `chough init` ran, with no other setup, two branches that each add a journal post merge with no conflict, the merged `feed.xml` parses as XML, and one `chough library index` makes `library index --check` pass, listing both posts.
- Over a `.gitattributes` that already declares some of the merge lines, `chough init` appends only the missing ones after its last line and changes no line. With `library-dir notes`, the lines name `notes/`. A driver the clone already sets is kept.
- Two branches that each add a Log entry to a bug whose write-up holds a code fence that never closes merge with both entries and no hand-resolved conflict.
