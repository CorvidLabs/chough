## MODIFIED

### REQUIREMENT REQ-cli-023

Record names and random draws. Automatically named evidence entries, repeated validation runs and every other new record SHALL be named by REQ-records-003; a repeated validation run SHALL be one evidence entry, named from its case ID and `run`, that holds each attempt: its front matter SHALL give `validation_run: true`, `run_case`, `environment`, `authority`, `times`, `interval_seconds`, `state`, `started`, `completed` (the time it completed, once it has), `failures`, `not_run`, `elapsed_seconds`, `bugs` and `attempts`, one flat map per attempt with `started`, `observed`, `result`, `duration_seconds` when known and `observation`, the attempt's own case-run entry. The run entry is a structural summary whose result is `not-run`: it SHALL never count as a run of its case, and `chough validate resume` SHALL find it by its ID or an alias. Random bits, for a clash suffix, a timeline entry ID or a neutral external ID, SHALL come from direct use of the existing getrandom 0.4.3 package, and no runtime or service SHALL be added. Identical repeated runs SHALL stay distinct history: same-day runs of one case in one session get clash suffixes. Creation SHALL use atomic create-new; a same-name different-content creation SHALL be refused without overwriting the existing bytes and without a numeric, timestamp or digest fallback, another random draw or any other retry. Random-source and write failures SHALL preserve existing records. Timestamps SHALL stay in their own fields and determine chronology rather than identity. Every 0.5.x observation, validation run, snapshot and bug ID SHALL stay resolvable as an alias without renumbering (REQ-records-003). An old-style ID supplied for a new write SHALL be refused with a remedy to omit the ID. Documentation SHALL state that Chough 0.5.x cannot read 0.6.0 names. Trace: FLOW-7, FLOW-9, FLOW-12, FLOW-13, LIFE-2, LIFE-3, LIFE-7, DRIVE-27.

Acceptance Criteria
- Identical case runs and repeated validation runs on one day in one session get distinct names of the required form, and timestamps stay in their fields.
- A repeated validation run's one entry gives `validation_run: true`, its `run_case`, `state`, `started`, `completed`, `failures`, `not_run`, `elapsed_seconds` and one `attempts` map per attempt with `started`, `observed`, `result`, `duration_seconds` and its `observation`; each attempt is also its own case-run entry, the run entry never counts as a run of its case, and `chough validate resume` continues a stopped run by its ID or by a 0.5.x ID kept as its alias.
- A forced same-name different-content creation refuses atomically, leaves every pre-existing record byte-identical, and creates no fallback, second draw or replacement; random-source and write failures preserve existing records.
- 0.5.x aliases work through case and bug links, checkpoint references, status, next, timing and validation resume, and an old-style ID supplied for a new write fails with an omit-ID remedy.
- A test with a pinned clock runs the same bound case in two independent Git roots, each in its own session on its own branch, at the same second; after the branches merge, both entries keep the pinned time and both read current.
- In a real Git fixture, two roots on separate branches independently add case-run evidence, `evidence add` entries and bugs; the merge has no conflict and every record from both sides is byte-identical to its branch version.
- `chough bug add` and `chough journal add` stopped by a full disk or a file-size limit leave no bug or post at the new name, and `chough bug list`, `status`, `next` and `library index --check` work as before; on an exFAT volume, where a hard link is refused, they still write whole records.
