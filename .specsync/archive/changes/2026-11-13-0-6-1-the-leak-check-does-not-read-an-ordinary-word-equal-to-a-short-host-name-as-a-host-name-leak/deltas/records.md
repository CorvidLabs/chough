## MODIFIED

### REQUIREMENT REQ-records-006

No leaks in committed records. Before writing any committed record, Chough SHALL check every value it writes, in front matter and body, including recorded commands, summaries, reasons, decisions, relayed words and places, notes, limitations, titles and actor values, for: an absolute path under a home, temporary or system root (`/Users/`, `/home/`, `/root/`, `/private/`, `/tmp/`, `/var/`, `/Volumes/`, `/mnt/`) or a Windows drive path; a `~/` path; the local host name anywhere when it is at least 8 characters long or holds a digit, a hyphen or a dot, and a shorter all-letter host name, which may be an ordinary word, only inside a path or a URL or as `<user>@<host>`; and the local user name when it appears inside a path or as `<user>@<host>`; an email address; and credentials: GitHub, GitLab, Slack, AWS and model-provider token forms, private key blocks, bearer and basic authorization values, JSON web tokens, and `password`, `secret`, `token` or `api_key` assignments with a value of 8 or more characters. A value that matches SHALL refuse the write as `refused:leak`, naming the field and the kind of match and never the matched text, with every file byte-identical. With `--redact`, each match SHALL instead be replaced by `<redacted:<kind>>` and the write SHALL proceed, saying how many values were redacted. A human's configured display name (REQ-records-008) SHALL NOT count as a user name. `chough doctor` SHALL scan every file Git tracks under `.chough/` and `knowledge/` for the same patterns and SHALL report each as a `leak` finding with the file, the line and the kind, never the text, except that a path under `/tmp/` or `/private/tmp/` in a case definition (`.chough/cases/*.cases.toml`) is a deliberate test setting, such as a case's own `XDG_DATA_HOME`, and SHALL NOT be reported or offered `--redact`, while a home path, the local user or host name, an email or a credential in a case definition still SHALL; the verify and CI lanes SHALL run that scan and fail on a finding. Trace: LIFE-26, LIFE-17, FLOW-22.

Acceptance Criteria
- Each pattern kind, placed in an evidence summary, a decision, a relayed `--words`, a bug note and a recorded command, refuses the write with `refused:leak` naming the field and kind, the output never contains the matched text, and every file is unchanged.
- The same writes with `--redact` store `<redacted:<kind>>` and report the count.
- A decision naming the configured human display name is written; the same name inside `/Users/<name>/` is refused.
- With one committed record holding a home path, `chough doctor` reports a `leak` finding with its file, line and kind, without the path, and exits 1; `fledge lanes run verify` fails on it.
- The records of a full fixture cycle run inside a temporary directory hold no absolute path, user name or host name.
- A committed case definition whose binding sets `XDG_DATA_HOME` to a path under `/tmp/` gives no `leak` finding from `chough doctor`, while one holding a home-folder path still gives one naming the file and line.
- With a short all-letter host name, a record using it as an ordinary word is written and `chough doctor` reports nothing, while the same name inside a path, a URL or as `<user>@<host>` is still refused; a host name of 8 or more characters, or one holding a digit, hyphen or dot, is still refused anywhere.
