## MODIFIED

### REQUIREMENT REQ-cli-009

Validated test definitions. The helper SHALL validate test definitions in `.chough/cases/<module>.cases.toml` against profile `chough-testing/1`: unique stable case IDs, active HI criteria, native requirement IDs, track, method, environments, artifact types, explicit expected outcomes, setup and steps for manual or agent-assisted cases, and a binding for automated cases. A binding MAY declare `env`, a bounded table of environment variable names and values; for the `cargo-test` adapter it SHALL NOT declare a variable that chooses what cargo builds or runs, and no binding SHALL declare an expected-output fragment containing the escape character. Unknown fields and unknown profiles SHALL be rejected. Each case SHALL have a definition digest that is independent of its position in the file, and an omitted or empty `env` SHALL leave that digest unchanged. New case definitions SHALL use curated IDs in the form `TC-<module>-<title-slug>`, where the title slug consists of nonempty lowercase ASCII alphanumeric runs separated by single hyphens. The complete ID SHALL remain within the existing 100-byte record ID bound using a module-aware slug limit. Case IDs SHALL be globally unique across all modules, including legacy and new forms. Exact legacy `TC-<module>-NNNN` definitions SHALL remain valid with unchanged definition digests and without renumbering or migration. New regression case definitions introduced for this change SHALL use slug IDs. Documentation SHALL state that older Chough versions require an upgrade to use slug case IDs. The shipped skill SHALL tell agents that a requirement an approved native change adds becomes linkable only after the scoped `specsync change check` materializes it, SHALL tell them to run that check before adding, running or recording cases that link it, and SHALL tell them not to list running or recording cases as a `tasks.md` checkbox, because that check refuses while one is unchecked. Trace: FLOW-7, LIFE-2, LIFE-6.

Acceptance Criteria
- Reordering cases leaves their IDs and digests unchanged; editing expected outcomes, steps or a binding, including its `env`, changes the digest.
- Duplicate IDs, unknown criteria or requirements, unknown fields, missing expected outcomes and automated cases without a binding are refused with the offending location.
- An invalid `env` name, a name over 128 bytes, two names equal ignoring ASCII case, a value with NUL, more than 32 entries or a value over 4 KiB, and an expected-output fragment containing ESC are refused with the offending location.
- A `cargo-test` binding that declares PATH, CARGO, CARGO_HOME, RUSTC, RUSTDOC, RUSTC_WRAPPER, RUSTC_WORKSPACE_WRAPPER, RUSTFLAGS, CARGO_ENCODED_RUSTFLAGS, RUSTDOCFLAGS, CARGO_ENCODED_RUSTDOCFLAGS, RUSTC_BOOTSTRAP, or a name starting with RUSTUP_, CARGO_BUILD_, CARGO_TARGET_ (other than CARGO_TARGET_DIR), CARGO_HOST_, CARGO_PROFILE_ or CARGO_UNSTABLE_, in any ASCII case, is refused with the offending location.
- Curated slug IDs accept lowercase ASCII normalization and enforce the module-aware 100-byte bound; empty, uppercase, repeated-separator and leading or trailing separator forms are refused. A duplicate ID in another module is refused globally.
- Exact legacy numeric cases remain readable and executable with unchanged definition digests and no renumbering or migration. The new regression case IDs for this change use slugs rather than allocating legacy numbers.
- The canonical plan, testing and accept references say the scoped check comes before cases that link a requirement the change adds, and that running or recording cases is not a `tasks.md` checkbox; the `cases check` refusal and its hint are unchanged.
