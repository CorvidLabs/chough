## MODIFIED

### REQUIREMENT REQ-cli-040

Serialized record writers. Every command that writes a Chough record SHALL hold one writer lock for the project while it reads what it changes and saves it, so a concurrent writer applies its change to the latest records and no update is lost. This includes every command that changes the checkpoint, `session new`, `session use`, `session close`, `session shelve`, `inbox add`, `inbox fold`, `bug add`, `bug update`, `evidence add`, `cases record`, `correct`, `journal add`, `doctor --fix` and `migrate --apply`; a command that first runs a case or a native process SHALL take the lock for its save and re-read what it changes under the lock. The lock SHALL be the file `.chough/local/checkpoint.lock` inside the project, in a directory Git ignores, so every process working on the project uses the same lock whatever its temporary directory. A writer that cannot take the lock within 30 seconds SHALL refuse as `refused:checkpoint-busy`, naming the record it would write, with nothing saved. On taking the lock a writer SHALL record its process ID in the lock file, and a `refused:checkpoint-busy` refusal SHALL name the process ID the file holds, if any, so a lock held by a forked child's inherited descriptor (#132) can be told from a live writer. Read-only commands SHALL take no lock. The lock orders Chough's own writers only: a Git command that rewrites the worktree, such as `git pull`, `git merge`, `git rebase`, `git checkout` or `git stash`, or `git switch`, `git restore`, `git reset --hard` and `git cherry-pick`, can replace a record that another process's Chough writer has just saved and exited 0 for, with nothing said (#387). So the workflow skill's checkpoint reference and the concurrency section of `docs/cli.md` SHALL each tell agents not to run such a Git command in a worktree while any other Chough command may be running there, that is, only when no other agent is working in that worktree; a lone agent may run one between its own commands. Trace: DRIVE-11, DRIVE-3.

Acceptance Criteria
- A writer started with a different `TMPDIR` waits while another process holds the project's lock, then saves its update.
- With the lock held, a stage move refuses as `refused:checkpoint-busy` naming `.chough/sessions/<id>/session.md`, with nothing saved.
- Two concurrent `bug update` notes on one bug both land in its Log.
- `.chough/local/checkpoint.lock` is ignored by Git.
- A busy refusal names the holder's process ID; a stress case runs the lock and stand-in tests 200 times alongside the rest of the suite on macOS and Linux and records how many failed, with their standard error (#132 and the macOS lane lock timeout).
- The workflow skill's checkpoint reference, in the bundle and in an installed copy, and `docs/cli.md` each say not to run `git pull`, `git merge`, `git rebase`, `git checkout` or `git stash` in a worktree while another agent works there, why, and that a lone agent may run one between its own commands.
