## MODIFIED

### REQUIREMENT REQ-cli-011

Honest case execution. When explicitly invoked, the helper SHALL execute an automated case's binding directly without a shell, with the binding's declared environment set on top of the inherited one, capture its output as an artifact, and record an observation linked to the case and its definition digest. Execution SHALL end by the binding's deadline: on the deadline, or when output stays open after the command exits, the helper SHALL stop the command and its descendants and SHALL NOT wait on output it cannot complete. On Unix, when the helper is stopped by SIGINT, SIGTERM or SIGHUP while a binding or native read it started runs, it SHALL stop that command and its descendants and end by that signal, recording no observation, artifact or checkpoint change; a signal inherited as ignored SHALL stay ignored. Captured output SHALL be bounded per stream while reading. The artifact SHALL keep the captured bytes, while assertions SHALL be evaluated on that text with complete terminal escape sequences removed. Removal SHALL never remove a line break, and a sequence that does not complete before a line break or the end of the output SHALL be left unchanged. The observation SHALL be passed only when the process exits zero, its capture is complete and the binding's assertion holds: exactly one test ran for the `cargo-test` adapter, or every declared expected-output fragment appeared for the `command` and `fledge-task` adapters. Every observation of an executed case SHALL state as a limitation that inherited environment variables were not recorded; when the binding declares variables it SHALL also name them without their values, and when escape sequences were removed it SHALL say so. A run in which no test matched SHALL be recorded as not-run. A repeated run SHALL record each attempt and a summary with attempt and failure counts and elapsed time, and SHALL start no further attempt once a stop request or a paused checkpoint exists, including after waiting its interval. Automatic observation and repeated validation run allocation SHALL follow REQ-cli-023. An explicit observation ID SHALL remain optional for automated and manual case recording; when omitted, the helper SHALL allocate the new OBS form, and when supplied for a new write it SHALL use that form rather than an old-style ID. An old-style supplied ID SHALL be refused with a remedy to omit the ID. The automated artifact name SHALL remain exactly `.chough/artifacts/<observation-id>.log`, inheriting the allocated or explicit observation ID. Legacy observation and validation run IDs SHALL remain readable and resumable. Trace: FLOW-7, FLOW-9, LIFE-7, FLOW-14.

Acceptance Criteria
- A deliberately failing assertion records failed even when another case passes in the same session.
- A cargo filter that matches no test records not-run, never passed.
- Changing a case definition reports its earlier observations as stale-case-definition.
- A case whose descendant holds its output returns by its deadline, and its descendants are stopped.
- SIGINT, SIGTERM or SIGHUP during `cases run` or a native read in `next` leaves no process of that command and no new or changed `.chough` file.
- A stop request made during the interval halts a repeated run before the next attempt, and resuming continues with the stored limits.
- A declared variable reaches the command, and the observation names it without its value.
- An observation of a case that declares no variables still states that inherited environment variables were not recorded.
- An escape sequence interrupted by a line break or the end of the output is left unchanged, and removal never lowers the number of lines that start with `test result:`.
- Coloured output whose visible text holds a fragment passes with the escape limitation, the artifact stays byte-exact, and a fragment absent from the visible text still fails.
- Omitting the observation ID allocates `OBS-<slug>-<24-lowercase-hex>`, identical repeated runs receive distinct random IDs, and each automated artifact is exactly `.chough/artifacts/<observation-id>.log` with the same observation ID.
- Repeated validation allocates `VAL-<slug>-<24-lowercase-hex>` with a random 96-bit suffix. Legacy observation and validation IDs remain readable and resumable, while an old-style ID supplied for a new case observation fails with an omit-ID remedy.
