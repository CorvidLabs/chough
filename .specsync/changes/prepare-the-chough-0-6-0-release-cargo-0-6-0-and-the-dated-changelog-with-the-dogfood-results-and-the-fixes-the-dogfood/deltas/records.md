## MODIFIED

### REQUIREMENT REQ-records-009

Migration from 0.5.x. `chough migrate` SHALL read a project's 0.5.x records, write nothing, and print the plan: each 0.5.x file with its SHA-256 and what it becomes, each 0.6.0 file it would write, every value it would redact by kind (REQ-records-006), and every file it would remove without carrying it, with why, and SHALL end with the plan's SHA-256; while any native change in the project is not archived, the preview SHALL also say that `--apply` will refuse until it is, naming each such change. `chough migrate --apply <plan digest>` SHALL refuse, writing nothing, unless the plan it builds has that digest, so nothing is migrated that was not previewed first; it SHALL also refuse, writing nothing, while any native change in the project is not archived, naming each, so it never runs while a change is open, and unless the human's consent is given, either as `--consent <source>` naming who consented, their words and where, which the receipt records as a relayed claim, or as a standing `migration` preference with its source (REQ-cli-013), and Chough SHALL NOT infer consent from the digest or from any other record; it SHALL also refuse, writing nothing, while a 0.5.x file to be removed differs from its bytes at HEAD or is untracked, naming each, so Git holds every byte it removes. It SHALL then write the 0.6.0 tree by create-new only and SHALL refuse, writing nothing more, when a file it would write already exists with other bytes; it SHALL read each written file back and compare its digest; it SHALL write the receipt `.chough/archive/migrations/<YYYY-MM-DD>-from-0-5.md` listing, for every file before and after, its path, size and SHA-256, the redactions by file, field and kind, every removed file with why and the commit that holds it, and the old-to-new ID map; and only then SHALL it remove the 0.5.x files, each only when its bytes still match the plan. It SHALL never weaken a SpecSync archive: before removing anything it SHALL read the native validity of every archived change whose acceptance manifest lists a file it would remove, at most 8 reads at once, read them again after the removal, and, if any archive that read valid no longer does, restore every removed file byte for byte and refuse, naming those archives. A file written by an interrupted apply with the planned bytes SHALL count as done on the next apply, and a second apply on a migrated tree SHALL report nothing to do. The mapping SHALL be: each open session, legacy `.chough/session.json` included, becomes a session folder whose timeline holds, in order, every transition of its selected history lineage, the legacy log's entries going to the session that adopted them; each archived session, and each session rolled into `knowledge/attachments/`, becomes an archived story; each observation an open session references becomes an evidence entry of that session, each one an archived session or a bug references becomes a receipt of that story or bug, and others are removed; a PNG or JPEG artifact of a carried observation that fits the bounds of REQ-records-013 is kept beside its session or story, and other artifacts are removed; each bug becomes a Markdown bug; inbox entries move to their session's `agent/inbox/`; every 0.5.x ID is kept as an alias (REQ-records-003), and an ID whose record was removed without being carried SHALL resolve as `removed`, naming the receipt, never as current or passed; and `.chough/transitions.jsonl`, `.chough/history/`, `.chough/pruned.jsonl`, `.chough/session.v1.json`, `.chough/artifacts/` other than files an open bug names, shelved 0.5.x sessions and the generated or copied vault content of REQ-cli-044 are removed after they are listed. Every file migration writes SHALL pass REQ-records-006 with redaction, so no home-folder path, user name or credential survives in a rewritten record; a file it keeps byte for byte (an open bug's fixture, a `library/` snapshot or brief) that matches SHALL be listed in the plan and the receipt as a `leak` finding for a person to fix, never changed silently and never kept unreported. The receipt SHALL say that Git history still holds what earlier commits leaked, which this migration does not rewrite. Case definitions and preferences SHALL stay byte-identical. Removal SHALL follow REQ-records-012. Trace: DRIVE-27, LIFE-20, LIFE-21, LIFE-8, KNOW-10, KNOW-11, KNOW-30, KNOW-31, KNOW-34, LIFE-26.

Acceptance Criteria
- Fixtures captured from a project at every released 0.x version, 0.1.0 to 0.5.0, each built from its release tag, migrate to the same kind of 0.6.0 tree with every record readable (#213).
- `--apply` without a digest, or with the digest of an earlier plan, refuses and writes nothing; `--apply` with the preview's digest proceeds.
- With a native change that is not archived, or with neither `--consent` nor a standing `migration` preference, `--apply` with the preview's digest refuses and writes nothing, naming the open change or the missing consent; with consent the receipt records its source.
- With a SpecSync stub whose archive reads invalid once a listed file is gone, `--apply` restores every removed file byte for byte and refuses naming that archive.
- A rewritten record that held a home-folder path holds `<redacted:home-path>` and the receipt counts it; a kept fixture holding one is listed as a `leak` finding and left unchanged; the receipt says Git history is not rewritten.
- On a 0.5.x fixture with a legacy checkpoint, adopted history, two open and seven archived sessions, rolled sessions in the vault, a bug of each ID form, inbox entries and old proof, `chough migrate` writes nothing and lists every file, target, redaction and removal.
- `--apply` with an uncommitted or untracked 0.5.x file refuses naming it, with nothing written.
- `--apply` writes every planned file and the receipt, removes the 0.5.x files, and afterwards every record, alias and timeline entry is readable by `next`, `status`, `bug show`, `session list` and `timing`; the receipt's before and after digests match the files at the earlier and the new commit.
- With a target that already exists with other bytes, `--apply` refuses and writes nothing more; after an apply interrupted between writes, the next apply completes and the result equals an uninterrupted one; a second apply on the result reports nothing to do.
- Case definition files and `.chough/preferences.json` are byte-identical before and after.
- Every transition of the selected lineage appears once, in order, in its session's timeline, and every archived session, the rolled ones included, is an archived story.
- A bug linking an observation that was removed without being carried shows it as `removed` with the receipt named, and `chough next` never counts it as current or passed.
- Regression for the local bug where history writes refused once the adopting session rolled into the vault: a 0.5.x fixture whose adopting session sits in `knowledge/attachments/`, with `.chough/transitions.jsonl` unchanged, migrates; the legacy entries land in that session's archived story, and afterwards `checkpoint --awaiting-human`, `--close-gate` and a stage move all succeed. The same writes are first recorded refusing on the last build before #142 (90e5de6f^), with the same tree recorded as observed on 0.5.0.
- With a native change open, the preview names it and says `--apply` will refuse, and writes nothing; the apply then refuses with `refused:change-open`.
