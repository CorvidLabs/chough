### REQUIREMENT REQ-records-009

Migration from 0.5.x. `chough migrate` SHALL read a project's 0.5.x records, write nothing, and print the plan, as text by default, since a person consents to it, and as JSON with `--json`, both with the same plan and digest: each 0.5.x file with its SHA-256 and what it becomes, each 0.6.0 file it would write, every value it would redact by kind (REQ-records-006), and every file it would remove without carrying it, with why, and SHALL end with the plan's SHA-256; while any native change in the project is not archived, the preview SHALL also say that `--apply` will refuse until it is, naming each such change. `chough migrate --apply <plan digest>` SHALL refuse, writing nothing, unless the plan it builds has that digest, so nothing is migrated that was not previewed first; it SHALL also refuse, writing nothing, while any native change in the project is not archived, naming each, so it never runs while a change is open, and unless the human's consent is given, either as `--consent <source>` naming who consented, their words and where, which the receipt records as a relayed claim, or as a standing `migration` preference with its source (REQ-cli-013), and Chough SHALL NOT infer consent from the digest or from any other record; it SHALL also refuse, writing nothing, while a 0.5.x file to be removed differs from its bytes at HEAD or is untracked, naming each, so Git holds every byte it removes. It SHALL check every file it would write, the receipt included, before it writes any, and SHALL refuse, writing nothing, when one already exists with other bytes; anything else at such a path, a directory, a file it cannot read or a special file, SHALL count as existing with other bytes and SHALL never be opened in a way that can wait; the refusal SHALL name the path relative to the project, SHALL say that a path appeared while migrating only of one that was absent when the apply checked, and the preview SHALL say that the apply would refuse and why. It SHALL remove no 0.5.x file until every file the plan writes, the receipt included, holds its planned bytes on disk: a file whose name differs only in letter case from one the plan removes, as `knowledge/index.md` beside a 0.5.x `knowledge/INDEX.md`, SHALL be written under a temporary name in the same folder and take its name by rename, replacing that file, never by create-new after the removal, so a file system that folds case or still holds the old name, as a Docker Desktop mount of a macOS folder does, cannot leave the sources removed and a planned file missing (#338). `knowledge/index.md` and `knowledge/journal/feed.xml`, which Chough generates from their sources (REQ-cli-043), are the exception: a regular file there with other bytes SHALL be replaced by the rebuilt one, as `chough library index` replaces it, and the plan SHALL say so. A 0.5.x file that a receipt of an earlier migration lists among the files it read SHALL never be migrated a second time: with the bytes that receipt lists, the plan SHALL remove it as already migrated, naming the receipt, whether or not the 0.6.0 record it was carried into is still where the receipt says, since that record may since have been archived, folded or removed; with other bytes, the preview and the apply SHALL refuse, naming each such file in one refusal with its receipt and the way on, to carry what is wanted into the 0.6.0 records by hand, an edit into the record the receipt names, or, where the file is a fixed path that holds whatever was current, as `.chough/session.json` does, a different session as a new one, then remove the 0.5.x file, commit and run `chough migrate` again, so an edited or different bug, session or history event never becomes a second record and is never dropped as if it had no place. To judge this, while any 0.5.x file is present the plan SHALL read every entry of `.chough/archive/migrations/`, and one that is not a receipt it can read, a directory or special file, a file it cannot read or that is not UTF-8, one over the receipt bound, or one with no list of files read, SHALL make the preview and the apply refuse naming it, without waiting and without treating any file as new. A 0.5.x record at any other path whose ID a 0.6.0 record already holds as an alias SHALL be refused the same way, naming that record, so no second record takes the alias (REQ-records-003). `chough migrate --apply` SHALL hold the writer lock (REQ-cli-040) from before it reads the records it plans from until it has finished, so of two applies of one digest the second finds nothing left to migrate, says so, applies nothing and records no consent; the Git-ignored lock file under `.chough/local/` is not a write of the migration; it SHALL then write the 0.6.0 tree by create-new only and SHALL refuse, writing nothing more, when a file it would write appears with other bytes meanwhile; it SHALL read each written file back and compare its digest; it SHALL write the receipt, whose path the plan names and so its digest covers: `.chough/archive/migrations/<YYYY-MM-DD>-from-0-5.md`, or, while a receipt of that name exists for another plan, the first free `<YYYY-MM-DD>-from-0-5-<n>.md` with `<n>` counting from 2, so a second migration on one day keeps the first receipt as it is and a receipt this plan's interrupted apply wrote is used again; the receipt lists, for every file before and after, its path, size and SHA-256, the redactions by file, field and kind, every removed file with why and the commit that holds it, and the old-to-new ID map, with `none` under any of its sections that has nothing to list; and only then SHALL it remove the 0.5.x files, each only when its bytes still match the plan. It SHALL never weaken a SpecSync archive: before removing anything it SHALL read the native validity of every archived change whose acceptance manifest lists a file it would remove, at most 8 reads at once, read them again after the removal, and, if any archive that read valid no longer does, restore every removed file byte for byte and refuse, naming those archives. A file written by an interrupted apply with the planned bytes SHALL count as done on the next apply, and a second apply on a migrated tree SHALL report nothing to do; on a tree with no 0.5.x record the preview SHALL likewise say there is nothing to migrate and give no plan digest. When the project's installed skill copy is not current, as `chough skill status` reports it (REQ-cli-016), the plan's and the receipt's follow-ups SHALL name `chough skill update`, so the copy that still names 0.5.x commands and paths is updated. The plan's and the receipt's follow-ups SHALL also name what `chough doctor` will report on the migrated tree (REQ-history-012): each session it will report as `finished_session`, to archive with `chough doctor --fix`, and each it will report as `stale_gates`, with each open gate's text and the decision it needs, `chough doctor --fix --reason`, computed by doctor's own session check on the planned records, so one consent round covers both. The mapping SHALL be: each open session, legacy `.chough/session.json` included, becomes a session folder whose timeline holds, in order, every transition of its selected history lineage, the legacy log's entries going to the session that adopted them; each archived session, and each session rolled into `knowledge/attachments/`, becomes an archived story; each observation an open session references becomes an evidence entry of that session, each one an archived session or a bug references becomes a receipt of that story or bug, and others are removed; a PNG or JPEG artifact of a carried observation that fits the bounds of REQ-records-013 is kept beside its session or story, and other artifacts are removed; each bug becomes a Markdown bug; inbox entries move to their session's `agent/inbox/`; every 0.5.x ID is kept as an alias (REQ-records-003), and an ID whose record was removed without being carried SHALL resolve as `removed`, naming the receipt, never as current or passed; and `.chough/transitions.jsonl`, `.chough/history/`, `.chough/pruned.jsonl`, `.chough/session.v1.json`, `.chough/artifacts/` other than files an open bug names, shelved 0.5.x sessions and the generated or copied vault content of REQ-cli-044 are removed after they are listed. Every file migration writes SHALL pass REQ-records-006 with redaction, so no home-folder path, user name or credential survives in a rewritten record; a file it keeps byte for byte (an open bug's fixture, a `library/` snapshot or brief) that matches SHALL be listed in the plan and the receipt as a `leak` finding for a person to fix, never changed silently and never kept unreported. The receipt SHALL say that Git history still holds what earlier commits leaked, which this migration does not rewrite. Case definitions and preferences SHALL stay byte-identical. Removal SHALL follow REQ-records-012. Trace: DRIVE-27, LIFE-20, LIFE-21, LIFE-8, KNOW-10, KNOW-11, KNOW-30, KNOW-31, KNOW-34, LIFE-26.

### REQUIREMENT REQ-records-015

Migration skips macOS metadata files. `chough migrate`, its preview and `--apply` alike, SHALL skip a `.DS_Store` file and a file or folder whose name starts with `._` among a project's 0.5.x records, in `.chough/` and in the knowledge directory alike (REQ-cli-068): it SHALL neither read, carry nor list such a file, so the file never stops the preview or the apply and the plan, its digest and the receipt are the same as without it. A folder the migration empties of its 0.5.x records and that then holds nothing but such files SHALL be removed with them once the apply has succeeded, and the apply's output SHALL name each folder removed that way with the number of such files it held; such a file beside a record or folder that stays SHALL stay (#375). Trace: DRIVE-14, DRIVE-27, LIFE-20.

Acceptance Criteria
- A 0.5.x project with AppleDouble `._` files and `.DS_Store` files beside its bugs, sessions, archived sessions, inbox entries, evidence, history events and knowledge notes previews with the same plan digest as without them, the apply of that digest succeeds, each folder the migration emptied of its records is gone with the metadata files it held and is named in the apply's output, and each such file beside records that stay is still there.
