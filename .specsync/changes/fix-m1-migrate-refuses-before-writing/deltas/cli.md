## MODIFIED

### REQUIREMENT REQ-cli-055

Chough doctor. `chough doctor` SHALL report the Chough debt of REQ-history-012 and each committed record, or case definition that does not parse as TOML, that holds a Git conflict marker (REQ-records-001, #339) as JSON with `schema_version` 1, `mode` (`report`, `dry-run` or `fix`) and `findings`, each with `kind`, `target`, `fix` (the Chough command that fixes it), `decision` (whether the fix is a decision) and `status` (`found`, `fixed` or `skipped`, with a `reason` when skipped). With no flag, or with `--dry-run`, it SHALL change nothing and report each finding as `found`. With `--fix` it SHALL apply each fix that is not a decision. After its fixes it SHALL remove the active pointer only when the pointer names no open session by ID, alias or bare slug (REQ-history-006), so a pointer that an in-place migration kept stays. A lone `=======` outside a conflict in a committed record, or in a case definition that does not parse as TOML, SHALL be a `possible_conflict_separator` finding naming its line, "possible leftover conflict separator at line N", marked `advisory`: a warning only, which SHALL never make `chough doctor` exit 1 (#339). A Git conflict marker line inside a closed code fence of a committed record SHALL be a `possible_fenced_conflict` finding naming its line and marker, "possible conflict markers inside a code fence at line N", also marked `advisory`, since a real conflict there cannot be told from a quoted one (#339). Each such finding SHALL name the marker by its seven characters only, never the rest of its line (REQ-records-001, #365). A fix that would leave a record unreadable, such as redacting an ID (REQ-history-012), SHALL NOT be applied: its finding SHALL be `skipped`, with the reason and the recovery, and the record SHALL stay byte for byte as it was on that line. It SHALL apply a decision fix only when `--reason <text>` is given, and SHALL otherwise report it as `skipped` with a fix that names `--reason`. It SHALL exit 0 when no finding is left `found` or `skipped`, and 1 otherwise. It SHALL make no native read, and SHALL never record a human decision, approval, review or consent. Its per-session findings (`finished_session`, `stale_gates`) SHALL come from one session check that `chough migrate`'s plan also runs on the planned records (REQ-records-009), so a migration's follow-ups name what the doctor will report. Trace: DRIVE-17.

Acceptance Criteria
- With no flag and with `--dry-run`, the doctor reports the same findings, each with a `chough` fix, exits 1, and leaves every file under `.chough/` unchanged.
- `--fix` without `--reason` applies the fixes that are not decisions and reports each decision fix as `skipped`, naming `--reason`; a project with no debt reports no findings and exits 0.
- No doctor run calls SpecSync.
- On a tree just migrated from 0.5.x, `chough doctor` reports exactly the `finished_session` and `stale_gates` sessions the migration's follow-ups named.
- `--fix --redact` on a committed session record whose ID reference holds a token leaves that line unchanged and the session readable, and reports the finding `skipped`, naming `chough session shelve <id>`.
- A committed record whose body holds a conflict gives a `conflict_markers` finding with no fix, and `--fix` reports it `skipped`.
- A committed case definition holding a conflict gives a `conflict_markers` finding for each marker line, naming the file, the line and the marker; a valid definition quoting a marker in a string gives none.
- A lone `=======` in a committed record gives one advisory `possible_conflict_separator` finding naming its line, and doctor's exit status is what it is without it.
- A Git conflict left inside a code fence of a committed session gives one advisory `possible_fenced_conflict` finding per marker line, naming it, and doctor's exit status is what it is without it.
- A committed conflict whose `>>>>>>>` line names a branch holding a token gives `conflict_markers` findings whose `marker` is `>>>>>>>`, and doctor's output holds no part of the branch name (#365).
- On a tree just migrated in place whose active pointer still holds a 0.5.x session name, `chough doctor --fix` reports no `stale_pointer`, leaves the pointer byte-identical, and `chough next` still shows that session.
