## MODIFIED

### REQUIREMENT REQ-records-001

Record files. Every record Chough writes, a session, an archived session story, an evidence entry, a bug, an inbox entry, a journal post and a migration receipt, SHALL be one UTF-8 Markdown file that starts with YAML front matter between two `---` lines, and that file SHALL be the record's only source of truth: no JSON or other twin SHALL be written beside it, and no index, cache or generated note SHALL be read in its place. The front matter SHALL carry the IDs and fields agents parse; the body SHALL carry the record for a human reader. Front matter SHALL use a strict subset of YAML that Chough reads and writes without a new dependency: `key: value` scalars, plain or double-quoted with `\"`, `\\` and `\n` escapes; flow lists `[a, b]`; block lists of scalars; and block lists of flat maps of scalars. Chough SHALL refuse front matter outside that subset, a duplicate key or a missing closing `---`, naming the file, the line and the rule, and SHALL write nothing in that command. A record's body SHALL NOT hold a Git conflict marker: a line that starts with `<<<<<<<` or `>>>>>>>`, or a line of `=======` between such lines (a `=======` line outside them, as a Markdown heading underline, is not one); a line inside a closed fenced code block, as CommonMark reads one, quoting an example or tool output, is not one, but a fence that never closes hides nothing after it, and no fence hides a conflict in a section Chough writes itself, a session's `## Timeline` or an archived story's `## Receipts` (#339). A real conflict Git leaves inside such a fence cannot be told from a quoted one, so no write SHALL be refused for it, and `chough doctor` SHALL only warn of each marker line there (REQ-cli-055). A lone `=======` outside a conflict may be left by a half-resolved conflict, but a heading underline may be followed directly by text, so no write SHALL be refused for it, and `chough doctor` SHALL only warn of it (REQ-cli-055). Chough SHALL refuse a write whose body would hold one as `refused:conflict-markers`, naming the file, the line and the marker, with every file unchanged, and `chough doctor` SHALL report each committed record whose body holds one as a `conflict_markers` finding naming the file, the line and the marker, which has no fix. A marker SHALL be named by its seven characters only, never the rest of its line, which may carry a branch name or a commit subject (#365). Reading SHALL be tolerant: an unknown front matter key SHALL be kept byte for byte, in place, when Chough rewrites the front matter, and SHALL be ignored otherwise; a missing optional key SHALL take its documented default; CRLF line endings SHALL be read as LF. Chough SHALL own only the front matter and the sections it appends to, and SHALL keep every other body byte a person or agent wrote: a write SHALL replace the front matter, append list items to the end of a named section, or create a missing named section at the end of the body, and SHALL do nothing else to an existing body. Files SHALL be written with LF line endings by an atomic replace under the writer lock of REQ-cli-040, or by create-new for a new record. A record SHALL be at most 65,536 bytes, except a session record, an archived session story and a migration receipt, which SHALL be at most 1,048,576, 1,048,576 and 4,194,304 bytes; a record over its bound SHALL be refused with the bound named and every file byte-identical. When a 0.5.x record would migrate into a record that holds a marker, the preview SHALL say that the apply refuses and SHALL NOT offer the apply command, and `chough migrate --apply` SHALL refuse with nothing written, each naming the 0.5.x file to resolve, the record it would become, the line and the marker. Trace: DRIVE-25, DRIVE-26, DRIVE-28, KNOW-32, LIFE-3.

Acceptance Criteria
- Every record kind written by a fixture cycle (session, archived story, evidence, bug, inbox entry, journal post, migration receipt) starts with front matter that the reader parses, and no `.json` file is written under `.chough/` except the local caches of REQ-history-007 and `.chough/preferences.json`.
- A person's edit to a session's Goal paragraph, to a bug's Steps and to an evidence entry's body survives a following stage move, decision, evidence add and bug update byte for byte.
- An unknown front matter key added by hand is kept byte for byte after Chough rewrites that front matter, and a missing optional key reads as its default.
- Front matter with a nested map, an anchor, a duplicate key or no closing line is refused with the file, line and rule named, and nothing is written.
- A CRLF copy of a record reads the same as the LF original.
- A record one byte over its bound is refused naming the bound, with every file unchanged.
- A record write whose body holds a `<<<<<<<`, `=======` or `>>>>>>>` conflict line is refused as `refused:conflict-markers` naming the file, the line and the marker, with every file unchanged; a body with a `=======` heading underline and no conflict is written.
- With a committed record whose body holds a conflict, `chough doctor` reports a `conflict_markers` finding for each marker line naming the file, the line and the marker, exits 1, and reports none for a tracked file that is not a record.
- A conflict quoted inside a fenced code block, with backtick or tilde fences, is not a marker and the record saves; a lone `=======` with text after it is not refused either.
- A conflict after a code fence that never closes, or after a backtick line whose tag holds a backtick, is a marker and the write is refused.
- A conflict inside an archived story's `## Timeline` or fenced `## Receipts` block is a marker, inside a fence or not.
- A Git conflict left inside a code fence of a session's Goal is not refused on the next write.
- A 0.5.x inbox entry whose text holds a conflict makes the migration preview say the apply refuses, without offering the apply command, and the apply refuse, each naming that 0.5.x file first.
- A conflict whose marker lines name a branch or a commit subject holding a token is refused and reported naming only `<<<<<<<`, `=======` or `>>>>>>>` and the line, never the branch or the subject (#365).

### REQUIREMENT REQ-records-006

No leaks in committed records. Before writing any committed record, Chough SHALL check every value it writes, in front matter and body, including recorded commands, summaries, reasons, decisions, answers to questions, relayed words and places, notes, limitations, titles, module names and actor values, for: an absolute path under a home, temporary or system root (`/Users/`, `/home/`, `/root/`, `/private/`, `/tmp/`, `/var/`, `/Volumes/`, `/mnt/`) or a Windows drive path; a `~/` or `~<user>/` path; the local host name anywhere when it is at least 8 characters long or holds a digit, a hyphen or a dot, and a shorter all-letter host name, which may be an ordinary word, only inside a path or a URL or as `<user>@<host>`, or as the `<host>:/<absolute path>` of an scp-style remote path, where the local host names are the machine's host name, its first label and, on macOS, its LocalHostName, each also as `<name>.local`, and one holding a dot counts inside a hyphenated name too, as in `build-<host>-1` (#368); and the local user name, checked as the account's name and also as `USER` or `LOGNAME` when they are set (#379), when it appears inside an absolute path, except as the first component of one that names a system root such as `/dev/`, after `~`, or as `<user>@<host>`. A relative path or a URL holds no user name, and the name `root` never counts (#379); an email address; and credentials: GitHub, GitLab, Slack (bot, user, workspace and `xapp-` app tokens), AWS, Hugging Face (`hf_`) and model-provider token forms, private key blocks, bearer and basic authorization values, JSON web tokens, and `password`, `secret`, `secret_key`, `secret_access_key` (as in `AWS_SECRET_ACCESS_KEY`), `token` or `api_key` assignments, with the key quoted or not, as in `{"password": …}`, and a value of 8 or more characters (#368). A value that matches SHALL refuse the write as `refused:leak`, naming the field and the kind of match and never the matched text, with every file byte-identical. With `--redact`, each match SHALL instead be replaced by `<redacted:<kind>>` and the write SHALL proceed, saying how many values were redacted, `chough evidence add` included (#368); a module name is an ID, so it is refused under `--redact` too. An error SHALL show a value a person gave, such as a session name from `--session`, `CHOUGH_SESSION` or `session use`, a bug or evidence reference or a `--decided-by` value, only when the value holds no match and no control character; otherwise it SHALL name the field and what it holds, as in `CHOUGH_SESSION holds token`, never the value (#367). A human's configured display name (REQ-records-008) SHALL NOT count as a user name. `chough doctor` SHALL scan every file Git tracks under `.chough/` and `knowledge/` for the same patterns and SHALL report each as a `leak` finding with the file, the line and the kind, never the text, except that a path under `/tmp/` or `/private/tmp/` in a case definition (`.chough/cases/*.cases.toml`) is a deliberate test setting, such as a case's own `XDG_DATA_HOME`, and SHALL NOT be reported or offered `--redact`, while a home path, the local user or host name, an email or a credential in a case definition still SHALL; the verify and CI lanes SHALL run that scan and fail on a finding. An scp-style remote path, `<host>:/<absolute path>`, SHALL be checked like the path it carries, so a home or system root after the colon refuses as a path leak and the host part counts as the local host name when it matches. Trace: LIFE-26, LIFE-17, FLOW-22.

Acceptance Criteria
- Each pattern kind, placed in an evidence summary, a decision, a relayed `--words`, a bug note and a recorded command, refuses the write with `refused:leak` naming the field and kind, the output never contains the matched text, and every file is unchanged.
- The same writes with `--redact` store `<redacted:<kind>>` and report the count.
- A decision naming the configured human display name is written; the same name inside `/Users/<name>/` is refused.
- With one committed record holding a home path, `chough doctor` reports a `leak` finding with its file, line and kind, without the path, and exits 1; `fledge lanes run verify` fails on it.
- The records of a full fixture cycle run inside a temporary directory hold no absolute path, user name or host name.
- A committed case definition whose binding sets `XDG_DATA_HOME` to a path under `/tmp/` gives no `leak` finding from `chough doctor`, while one holding a home-folder path still gives one naming the file and line.
- With a short all-letter host name, a record using it as an ordinary word is written and `chough doctor` reports nothing, while the same name inside a path, a URL or as `<user>@<host>` is still refused; a host name of 8 or more characters, or one holding a digit, hyphen or dot, is still refused anywhere.
- With an scp-style remote path, `<host>:/<absolute path>`, the write is refused as a path leak when a home or system root follows the colon, and the host part is refused as a host-name leak when it is the local host, in the write guard and in `chough doctor` alike.
- `checkpoint --resolve-question <question> --answer <text>` with each pattern kind refuses with `refused:leak` naming `answer`, with every file unchanged; with `--redact` the answer holds `<redacted:<kind>>`; an answer over 4,096 bytes is refused (#364).
- `{"password": "…"}`, `SECRET_KEY=…`, `AWS_SECRET_ACCESS_KEY=…`, an `xapp-` and an `hf_` token, a `~<user>/` path, the LocalHostName's `<name>.local` and a dotted host name inside `build-<host>-1` each refuse the write; `session new --module` holding a pattern kind is refused (#368).
- With `USER` and `LOGNAME` unset, the account's user name as `<user>@<host>` is still refused; with the user named `dev`, a `/dev/…` path, `src/dev/main.rs` and `https://example.com/dev/guide` are written while `/opt/dev/x` is refused; with the account `root`, `ssh root@build-box` and `postgres://root@db/x` are written; a home path and a `~/` path are still refused (#379).
- `evidence add --redact` with a leaking value says how many values it redacted (#368).
- An unknown session, bug or evidence reference or `--decided-by` value holding a pattern kind or a control character is refused naming the field and what it holds, and the output holds neither the value nor the control character; a clean one is still named (#367).
