## MODIFIED

### REQUIREMENT REQ-cli-007

Canonical checkpoint. The helper SHALL keep one canonical checkpoint per open session: the front matter of the active session's `session.md` (REQ-records-004, REQ-cli-037), holding the objective, intent scope, modules, current stage with its status, iteration and side-stage callers, the native change identity, the pull request, referenced criteria, requirements, cases, design sources and files, observation and bug references, blockers, awaiting-human gates, run consents and the next action, with decisions, completed work and open questions in the story sections of the same file. `chough checkpoint --pr <number or URL>` SHALL set the pull request when the value is a pull request number, a positive whole number written without a sign or leading zero, optionally after one `#`, which is stored without it, or an `http://` or `https://` URL with a host and none of whitespace, `(`, `)`, `[`, `]`, `<`, `>`, a quote, a backtick or a backslash, passed through the leak guard of REQ-records-006 as the field always is; it SHALL refuse any other value, naming the two forms and never the value, with the session file byte-identical, and an empty value SHALL clear it, removing `pr` from the front matter; the pull request SHALL be written as a double-quoted string, and a stored `pr: ""` SHALL read as no pull request everywhere (#353). `chough next` and `chough status`, in text and JSON, `chough context` and the checkpoint view `chough checkpoint` prints SHALL show the session's pull request when it has one, and the journal post SHALL link it only as such a number or URL, leaving out a stored value that is neither, as an earlier release could write (#353); like `--objective` and `--title`, it SHALL add no Timeline entry. No other writable checkpoint store SHALL exist and no adapter such as APS SHALL be required. Every read SHALL validate the front matter's keys and value types and SHALL refuse a malformed one naming the file, the key and the rule (REQ-records-001). `chough checkpoint --merge` and the `chough-session` merge driver are removed, because each session has its own folder and parallel branches never write one checkpoint (DRIVE-24). When SpecSync is configured, `chough checkpoint --native-change <id>` SHALL read `specsync change status <id>` before it applies any update, and SHALL refuse as `refused:native-change-unknown`, naming the ID and that status command, when SpecSync does not report the change; a failed or timed-out read SHALL also refuse, and a reply whose `summary.id` or `change.id` names a different change SHALL refuse as `refused:native-change-mismatch`, naming both IDs. A JSON reply that names neither `summary.id` nor `change.id` SHALL refuse as `refused:native-change-unknown`, since it does not identify the requested change. Every such refusal SHALL leave the session file byte-identical, including the other updates given in the same call. An ID SpecSync reports, archived or open, SHALL be saved as before. Without a SpecSync configuration only the existing ID format check SHALL apply, with no native read. `chough checkpoint --no-native-change <reason>` SHALL record, as `no_native_change` in the session's front matter, that the session's work needs no native change and why; it SHALL refuse a blank reason, SHALL refuse with nothing saved while the session records a native change, naming it, and recording a native change SHALL remove it. Reading and saving a session SHALL refuse, with nothing written, a `no_native_change` that holds only white space or a `<placeholder>`, and one held together with a native change, so an edit of the file by hand cannot allow the ungated move; the refusal SHALL name the session file and the field and say what to edit, the real reason in place of the value or the line removed, or one of the two fields removed. An empty `no_native_change` reads as none recorded. While it is recorded and no native change is, a stage move that SpecSync's configuration would otherwise refuse as `refused:no-native-change` SHALL be allowed and labelled `ungated:no-native-change-required`, so the session can advance to done and be archived with outcome `done` (REQ-history-006), its story keeping the reason; an open human gate that holds the stage SHALL still refuse the move (REQ-cli-030), and only a person closes it. Trace: FLOW-13, LIFE-3, DRIVE-3, DRIVE-24, DRIVE-25.

Acceptance Criteria
- A checkpoint saved by one process is read unchanged by `chough context` and `chough next` in another process; a front matter key with the wrong type is refused naming the file and the key, with nothing written.
- No second writable checkpoint store is introduced and no adapter is required; `.gitattributes` declares no `chough-session` driver and `chough checkpoint --merge` is not a command.
- With SpecSync configured, `checkpoint --native-change` for an ID SpecSync does not report, or after a failed or timed-out status read, exits non-zero with `refused:native-change-unknown` or the read failure and leaves the session file byte-identical even with other updates in the same call; a reply naming a different change refuses as `refused:native-change-mismatch` with the file byte-identical; a JSON reply naming no change ID, such as `[]` or `{}`, refuses as `refused:native-change-unknown` with the file byte-identical; a reported ID saves; without SpecSync any well-formed ID saves and a malformed one is refused.
- `chough checkpoint --pr 150` and `--pr` with an `https://` pull request URL each set the session's `pr`, which another process reads back, and `--pr '#12'` stores `12`; `--pr ""` removes `pr`; `0`, `#0`, `012`, `src/pr.txt`, `not a pr`, `ftp://x/1`, `42](javascript:alert(1))`, `https://x/1)[click](javascript:alert(1)` and a value with a line break are refused naming the two forms, without the value, with the session file byte-identical; one holding a local path or a token is refused, or redacted under `--redact`; no Timeline entry is added.
- With `pr` set, `chough next`, `chough status`, `chough context` and `chough checkpoint` each show it, in text and JSON; a stored `pr` that is neither form is shown escaped (REQ-records-016) and left out of the journal post's links.
- `--pr 42` is written as `pr: "42"`; a session holding `pr: ""`, as many existing ones do, shows no pull request in `next`, `status`, `context` and the checkpoint view, and its journal post links none.
- A session file edited by hand to hold `no_native_change: " "`, or to hold both `native_change` and `no_native_change`, is refused by `chough next`, `chough checkpoint` and `chough stage advance`, naming the file, the field and the edit, with every file byte-identical; `chough session list` still lists that session as not readable with that reason and `chough session shelve <id>`, `chough doctor` still runs, and a command given another open session is unaffected.
