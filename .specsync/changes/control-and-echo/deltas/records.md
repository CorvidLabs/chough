## ADDED

### REQUIREMENT REQ-records-016

Control characters. A control character is a C0 control (U+0000 to U+001F), DEL (U+007F), a C1 control (U+0080 to U+009F) or a bidirectional override or isolate (U+202A to U+202E, U+2066 to U+2069). Before writing any committed record, Chough SHALL refuse a value a person gives that holds one, in every field REQ-records-006 checks, as `refused:control-character`, naming the field and the character's code point and never the value, with every file byte-identical, under `--redact` too; a line feed and a tab SHALL be accepted in a field that accepts a line break, and a carriage return directly before a line feed SHALL be dropped, so a line break pasted from Windows is stored as a line feed (#366). Chough SHALL print text it read from a record or was given, in text and JSON output alike, with each control character escaped as `\u` and four lowercase hex digits, the form JSON uses, so no terminal acts on it, while JSON output still parses back to the stored value; a line feed and a tab SHALL be printed as they are where the text is shown on several lines and as `\n` and `\t` where it is shown on one line, such as the reason on `chough next`'s `Native change: none needed:` line (#366). What Chough generates from stored text, the journal feed `knowledge/journal/feed.xml`, `knowledge/index.md` and an archived story, SHALL hold that text as it is printed, so a post or a record an earlier release wrote leaves the feed well-formed XML and neither file nor the story holds a control character raw (#366). A front matter scalar that a YAML reader takes as other than text, `null`, `~`, `true`, `false`, `yes`, `no`, `on` or `off` in any letter case, SHALL be written double-quoted, so every text field reads back as text (#366). Trace: LIFE-26, LIFE-3.

Acceptance Criteria
- With ESC, BEL, DEL, U+009B, U+202E and U+2066 each in an objective, a decision, a `--no-native-change` reason, a `--pr`, an evidence summary, environment and limitation, a bug title, an inbox entry and relayed `--words`, the write is refused as `refused:control-character` naming the field and the code point, the output holds no control character, and every file is unchanged, with `--redact` as well.
- A decision and an evidence summary holding a line feed or a tab are written, and `next` shows a decision's tab as `\t`; a CRLF line break is stored as a line feed; `--title` and `--pr` holding a line feed or a tab are refused.
- A fixture holding each control character, written by hand as an earlier release could, in every record kind (session, story, evidence entry, bug, inbox entry, journal post, case definition and gate), and every command in `chough --help`'s tree run over it, in text and JSON where it has both, with the fixture's IDs where a command takes one: no output holds a control character raw, and each JSON output still parses; a command added later is in the sweep without editing it. A `--no-native-change` reason holding a line feed shows on `next`'s line as `\n`.
- With a journal post and a session from an earlier release holding each control character, `chough library index` writes a feed that parses as XML and an index holding none raw, and archiving the session writes a story holding none raw.
- `--no-native-change null`, `--decision true`, `--decision yes`, a blocker `Off` and an objective `~` are written double-quoted and read back as text.

## MODIFIED

### REQUIREMENT REQ-records-006

No leaks in committed records. Before writing any committed record, Chough SHALL check every value it writes, in front matter and body, including recorded commands, summaries, reasons, decisions, answers to questions, relayed words and places, notes, limitations, titles, module names and actor values, for: an absolute path under a home, temporary or system root (`/Users/`, `/home/`, `/root/`, `/private/`, `/tmp/`, `/var/`, `/Volumes/`, `/mnt/`) or a Windows drive path; a `~/` or `~<user>/` path; the local host name anywhere when it is at least 8 characters long or holds a digit, a hyphen or a dot, and a shorter all-letter host name, which may be an ordinary word, only inside a path or a URL or as `<user>@<host>`, or as the `<host>:/<absolute path>` of an scp-style remote path, where the local host names are the machine's host name, its first label and, on macOS, its LocalHostName, each also as `<name>.local`, and one holding a dot counts inside a hyphenated name too, as in `build-<host>-1` (#368); and the local user name, checked as the account's name and also as each of `USER`, `LOGNAME` and `USERNAME` that is set (#379), when it appears inside an absolute path, except as the first component of one that names a system root such as `/dev/`, after `~`, or as `<user>@<host>`. A relative path or a web URL (`http:` or `https:`) holds no user name, while a local file URL (`file:`) is checked like the path it carries, and the name `root` never counts (#379); an email address; and credentials: GitHub, GitLab, Slack (bot, user, workspace and `xapp-` app tokens), AWS, Hugging Face (`hf_`) and model-provider token forms, private key blocks, bearer and basic authorization values, JSON web tokens, and `password`, `secret`, `secret_key`, `secret_access_key` (as in `AWS_SECRET_ACCESS_KEY`), `token` or `api_key` assignments, with the key quoted or not, as in `{"password": …}`, and a value of 8 or more characters (#368). A value that matches SHALL refuse the write as `refused:leak`, naming the field and the kind of match and never the matched text, with every file byte-identical. With `--redact`, each match SHALL instead be replaced by `<redacted:<kind>>` and the write SHALL proceed, saying how many values were redacted, `chough evidence add` included (#368); a module name is an ID, so it is refused under `--redact` too. An error SHALL show a value a person gave, such as a session name from `--session`, `CHOUGH_SESSION` or `session use`, a bug or evidence reference or a `--decided-by` value, only when the value holds no match and no control character; otherwise it SHALL name the field and what it holds, as in `CHOUGH_SESSION holds token`, never the value (#367). Output that repeats a value given on the command line, such as the environment `chough next` and `chough status` show or the criteria, requirements and paths `chough cases select` lists, SHALL follow the same rule (#367). A human's configured display name (REQ-records-008) SHALL NOT count as a user name. `chough doctor` SHALL scan every file Git tracks under `.chough/` and `knowledge/` for the same patterns and SHALL report each as a `leak` finding with the file, the line and the kind, never the text, except that a path under `/tmp/` or `/private/tmp/` in a case definition (`.chough/cases/*.cases.toml`) is a deliberate test setting, such as a case's own `XDG_DATA_HOME`, and SHALL NOT be reported or offered `--redact`, while a home path, the local user or host name, an email or a credential in a case definition still SHALL; the verify and CI lanes SHALL run that scan and fail on a finding. An scp-style remote path, `<host>:/<absolute path>`, SHALL be checked like the path it carries, so a home or system root after the colon refuses as a path leak and the host part counts as the local host name when it matches. Trace: LIFE-26, LIFE-17, FLOW-22.

Acceptance Criteria
- Each pattern kind, placed in an evidence summary, a decision, a relayed `--words`, a bug note and a recorded command, refuses the write with `refused:leak` naming the field and kind, the output never contains the matched text, and every file is unchanged.
- The same writes with `--redact` store `<redacted:<kind>>` and report the count.
- A decision naming the configured human display name is written; the same name inside `/Users/<name>/` is refused.
- With one committed record holding a home path, `chough doctor` reports a `leak` finding with its file, line and kind, without the path, and exits 1; `fledge lanes run verify` fails on it.
- The records of a full fixture cycle run inside a temporary directory hold no absolute path, user name or host name.
- A committed case definition whose binding sets `XDG_DATA_HOME` to a path under `/tmp/` gives no `leak` finding from `chough doctor`, while one holding a home-folder path still gives one naming the file and line.
- With a short all-letter host name, a record using it as an ordinary word is written and `chough doctor` reports nothing, while the same name inside a path, a URL or as `<user>@<host>` is still refused; a host name of 8 or more characters, or one holding a digit, hyphen or dot, is still refused anywhere.
- With an scp-style remote path, `<host>:/<absolute path>`, the write is refused as a path leak when a home or system root follows the colon, and the host part is refused as a host-name leak when it is the local host, in the write guard and in `chough doctor` alike.
- `checkpoint --resolve-question <question> --answer <text>` with each pattern kind refuses with `refused:leak` naming `answer`, with every file unchanged; with `--redact` the answer holds `<redacted:<kind>>`; an answer over 4,096 bytes is refused (#364).
- `{"password": "…"}`, `SECRET_KEY=…`, `AWS_SECRET_ACCESS_KEY=…`, an `xapp-` and an `hf_` token, a `~<user>/` path, the LocalHostName's `<name>.local` and a dotted host name inside `build-<host>-1` each refuse the write; `session new --module` holding a pattern kind is refused (#368).
- With `USER` and `LOGNAME` unset, the account's user name as `<user>@<host>` is still refused; with the user named `dev`, a `/dev/…` path, `src/dev/main.rs` and `https://example.com/dev/guide` are written while `/opt/dev/x` is refused; with the account `root`, `ssh root@build-box` and `postgres://root@db/x` are written; a home path and a `~/` path are still refused (#379).
- `evidence add --redact` with a leaking value says how many values it redacted (#368).
- An unknown session, bug or evidence reference or `--decided-by` value holding a pattern kind or a control character is refused naming the field and what it holds, and the output holds neither the value nor the control character; a clean one is still named (#367).
- With the user named `dev`, `file:///opt/dev/x` is refused as a `user-name` leak, while `https://example.com/dev/guide` is still written; with `USER`, `LOGNAME` and `USERNAME` set to three names, each is refused inside an absolute path.
- A sweep that gives every value a command takes, flag or argument, a token and an escape sequence finds neither in any error or output, including `pref set` and `pref unset`, `consent revoke`, `skill status` and `skill remove-legacy` with `--host`, `stage advance --to`, `stage enter` and `stage back --to`, `validate resume`, an explicit evidence ID, `library merge`, `correct`, `next --environment`, `status --environment` and `cases select`; each names the field and what it holds instead (#367).
