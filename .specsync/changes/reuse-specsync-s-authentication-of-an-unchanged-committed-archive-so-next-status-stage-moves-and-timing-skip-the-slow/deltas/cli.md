### REQUIREMENT REQ-cli-035

Authenticated archive reuse and batched advance. When `specsync change status <id> --json` reports a committed archive with `change.state` and `summary.state` archived and `summary.terminal_evidence.validity` authenticated-history, the helper SHALL record that response under the Git common directory (`chough/archive-auth/`), outside the worktree, keyed by a SHA-256 digest over the archive directory's relative paths and bytes, `.specsync/archive/legacy-baseline.json` when present, `.specsync/sdd.json`, the native config file, and the resolved SpecSync binary's path, size and modification time. It SHALL record only an archive directory under `.specsync/archive/changes/` that holds `accepted-state.json` and whose `verification.json` holds an acceptance manifest, because SpecSync judges such an archive from its own bytes; it SHALL record nothing for a stale, corrupt-history, failed, timed-out or oversized read. `chough next`, `chough status`, stage moves and `chough timing` SHALL reuse a recorded result without running SpecSync only when the change has no active workspace, exactly one archive directory matches, no input is a symlink, the inputs fit the read bound and the recomputed digest equals the recorded one; any other case SHALL make the live native read, whose gates and refusals are unchanged. A gate passed on a reused result SHALL carry the label `native:archived-authenticated-cached` and a detail naming the SpecSync binary, the time it authenticated the archive and the digest. Retention and approved-delta reads SHALL stay live. The helper SHALL NOT decide archive validity itself, and SHALL NOT record human approval or review. `chough stage advance --to <stage>` SHALL move through each main stage up to the target on one native read, SHALL check every step's gate, open human gate and acceptance prerequisite before recording any transition, SHALL record one transition per step, and SHALL refuse the whole batch with nothing recorded when any step is refused. Human decision: Leif's brief t811u item 2, "Want: archived changes are read from their committed archive files (or a cache keyed by archive digest) without asking SpecSync for live status; one native status read per command at most; `next` answers within a few seconds on Raven. Measure before and after.", and item 7, "one read should serve a batch", confirmed by Leif at 2026-11-03 5:24 PM MST. Trace: DRIVE-2, DRIVE-9, LIFE-3, LIFE-6.

Acceptance Criteria
- With a counting SpecSync stub, a first `chough next` on an authenticated archive makes one native read and records it; later `next`, `status`, `stage advance` and `timing` make none and the gate is `native:archived-authenticated-cached`.
- Changing any archive byte, the policy, the baseline or the stub binary, corrupting the entry, opening an active workspace of the same ID or removing the accepted-state snapshot makes the live read again, and a refused live read still refuses.
- A stale or corrupt-history response is never recorded, and retention validity reads stay live.
- `stage advance --to accept` from plan makes one native read and records three transitions; when a later step is refused, nothing is recorded and the checkpoint is unchanged.

### REQUIREMENT REQ-cli-024

Timing native reads. Within one `chough timing` report the helper SHALL pass each distinct native change ID to `specsync change status` at most once, reusing that response for every place the report shows the change; the reuse SHALL be local to the request and SHALL NOT persist or serve any other command, except that an authenticated archive result recorded under REQ-cli-035 SHALL be reused as that requirement allows. The report SHALL read archived native history only when its selection shows history, which is `--cycle all` with no `--stage`, `--case` or `--bug` filter; otherwise it SHALL read only the checkpoint's native change, SHALL set `native.history` to null rather than an empty list, and SHALL report `native.history_selection` with state `skipped-by-filter` and the filters that excluded it, and the text form SHALL say that archived history was not read because of those filters. When history is selected, `native.history_selection` SHALL have state `selected` and SHALL report how many archived changes were read, reused, skipped beyond the existing bound of ten, and not read because the budget ran out. Total time spent waiting on native reads in one timing report SHALL be bounded by `CHOUGH_TIMING_NATIVE_BUDGET_SECONDS`, a whole number from 1 to 3600 with default 120, refused before any native read when invalid; a read SHALL run with the smaller of the per-read deadline and the remaining budget, and a read not started because the budget is exhausted SHALL be reported with status_read `not-read` and reason `budget-exhausted`, with its times unknown, never zero. Stage estimates SHALL continue to derive only from recorded transitions and SHALL NOT change with native history selection. With `CHOUGH_TRACE=1` the helper SHALL write to standard error one line per bounded native read with the program, arguments, elapsed milliseconds and final state, and timing SHALL write per-phase elapsed milliseconds; without it standard output and standard error SHALL be unchanged, and the trace SHALL NOT change any report, record or exit code. The budget, history selection and reuse SHALL NOT apply to stage moves, `chough next` or `chough status`, whose single native read keeps the per-read deadline and whose gates keep refusing missing, timed-out, failed or invalid native evidence. Trace: LIFE-10, LIFE-3, LIFE-6, LIFE-7.

Acceptance Criteria
- With a counting SpecSync stub and the checkpoint change also present in the archive, an unfiltered timing report runs `specsync change status` once for that change and at most ten archived reads in total, and the current and history entries for it carry the same response.
- `--cycle current`, `--stage test`, `--case <id>` and `--bug <id>` each run only the checkpoint read, emit `native.history` null with `history_selection.state` `skipped-by-filter` naming the filter, and say so in text; the unfiltered report emits `selected` with read, reused, skipped and budget counts; stage estimates are identical in filtered and unfiltered reports of the same records.
- With a 2 s budget and stub reads that sleep, hang, exit non-zero and print malformed JSON, the report ends within the budget plus process-stop grace, reports timed-out, failed, invalid-output and not-read budget-exhausted entries with unknown times, leaves no stub descendant running, and an invalid budget value is refused before any native process starts.
- With `CHOUGH_TRACE=1` each native read and each timing phase produces one stderr line and standard output is byte-identical to the untraced run; without it both streams are byte-identical to the base behavior for the same records.
- A stage move whose native read times out or fails is still refused with the budget variable set to 1, and `chough next` and `chough status` still make exactly one native read each, or none when REQ-cli-035 reuses an authenticated archive result.
- Running the report leaves every Chough and SpecSync record byte-identical.
