WHAT WAS IMPLEMENTED (REQ-cli-024, `chough timing` only)
- Each change ID is read at most once per report, and the response is reused; no
  persistent cache.
- Archived history is read only for --cycle all with no --stage/--case/--bug.
  Filtered reports emit:
  - native.history null and native.skipped_archived null
  - history_selection {skipped-by-filter, filters, reason}
  - a partial entry and a text line
  Unfiltered reports emit history_selection selected, with read, reused,
  skipped_beyond_bound, not_read_budget and budget_seconds. Stage estimates are
  unchanged (from transitions only).
- CHOUGH_TIMING_NATIVE_BUDGET_SECONDS: whole seconds 1..3600, default 120. An
  invalid value is refused before any read. Each read gets min(per-read deadline,
  remaining budget). A read cut by the budget is timed-out and names the budget. A
  change with no budget left is not-read with reason budget-exhausted, its record
  files are not read, and every time is unknown with the budget reason.
- CHOUGH_TRACE=1 traces every bounded native read, in all commands:
    chough-trace: native state=<s> elapsed_ms=<n> command=<...>
  State and elapsed come first; only the command is shortened, within 1024 bytes.
  Timing also traces its phases (transitions, tests, validation, native, render).
  Without the variable, output is unchanged.
- Gates, next and status still use native_json with the per-read deadline. There is
  no budget, filtering or reuse on that path, and no parallel queries, runtime or new
  dependency.
